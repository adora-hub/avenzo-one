# Phase 1.1.3.7.4 — Two-person Approval

## เป้าหมาย

เพิ่มหลักการ “ผู้ขอ 1 คน + ผู้อนุมัติอีก 1 คน” ก่อนพิจารณาเปิด Limited Live Pilot โดยทั้งสองต้องเป็น Platform Admin คนละบัญชีและยืนยัน MFA ระดับ AAL2

Phase นี้สร้างเฉพาะคำขอและหลักฐานการอนุมัติ ยังไม่เปิด Live Checkout, ไม่เปลี่ยน `pilot_enabled=false` และไม่ปลด `emergency_stop=true` จึงยังรับเงินจริงไม่ได้

## กติกาที่บังคับฝั่ง Database

- ต้องผ่าน Production Readiness และ Safety Control อยู่ในสถานะ `review_ready`
- ต้องมีผู้ทดสอบที่อนุญาตอย่างน้อย 1 คน
- ต้องมี Platform Admin ที่ใช้งานอยู่ไม่น้อยกว่า 2 บัญชี
- คำขอมีอายุ 24 ชั่วโมงและมีคำขอ `pending` ได้ครั้งละ 1 รายการ
- ผู้อนุมัติคนที่ 2 ต้องไม่ใช่บัญชีเดียวกับผู้ขอ
- ก่อนอนุมัติ Database ตรวจว่า Policy Version, วงเงิน, จำนวนครั้ง และจำนวนผู้ทดสอบยังตรงกับ Snapshot เดิม
- หากกติกาเปลี่ยน ต้องยกเลิกหรือปิดคำขอเดิมแล้วสร้างใหม่
- ทุก Request, Approve, Reject, Cancel และ Expire มี Command ID และ Immutable Audit Event

## UI สำหรับ Platform Admin

- แสดงผู้ขอคนที่ 1, วันเวลาสร้าง, วันหมดอายุ และ Snapshot กติกา
- บัญชีผู้ขอเห็นคำแนะนำให้ผู้ดูแลคนที่ 2 Login และสามารถยกเลิกคำขอของตนเอง
- บัญชีผู้ดูแลคนที่ 2 สามารถตรวจสอบก่อนอนุมัติหรือไม่อนุมัติ
- แสดงประวัติคำขอและ Audit Event 10 รายการล่าสุดเป็นภาษาไทย
- ทุกคำสั่งมีหน้าตรวจสอบครั้งสุดท้ายและต้องบันทึกเหตุผลอย่างน้อย 10 ตัวอักษร

## Acceptance Criteria

1. ผู้ขอไม่สามารถอนุมัติคำขอของตนเองได้ทั้งใน UI และ Database RPC
2. Platform Admin ทั้งสองบัญชีต้องใช้ Session ระดับ AAL2
3. คำขอเกิน 24 ชั่วโมงอนุมัติไม่ได้
4. Snapshot เปลี่ยนหลังส่งคำขอแล้วอนุมัติไม่ได้
5. การอนุมัติครบไม่เปิด Pilot และไม่ปลด Emergency Stop
6. RLS, explicit grants, TypeScript และ Production build ผ่าน

## วิธีทดสอบ Local

1. Login ด้วย Platform Admin คนที่ 1 และผ่าน MFA
2. เปิด `/platform-admin/billing/live-control` แล้วสร้างคำขอพร้อมเหตุผล
3. ยืนยันว่าบัญชีคนที่ 1 ไม่มีปุ่มอนุมัติคำขอของตนเอง
4. Logout แล้ว Login ด้วย Platform Admin คนที่ 2 พร้อม MFA
5. เปิดหน้าเดิม ตรวจ Snapshot แล้วเลือกอนุมัติหรือไม่อนุมัติ
6. ยืนยันว่าประวัติแสดงผู้ขอและผู้พิจารณาเป็นคนละอีเมล
7. ตรวจว่าสถานะยังแสดง “ยังไม่เปิดรับเงินจริง” และ Emergency Stop ยังทำงาน

## ขั้นต่อไป

หลังผู้ใช้ทดสอบ Local ผ่าน ให้ขออนุมัติ Commit/Push/Deploy แยกต่างหาก แล้วจึงวางแผน Phase 1.1.3.7.5 Controlled Live Checkout ซึ่งต้องใช้ผลอนุมัติที่ยังไม่หมดอายุและเพิ่มการเฝ้าระวังธุรกรรมแบบเรียลไทม์
