# Phase 1.1.3.7.4.1 — Platform Admin Access Management

## เป้าหมาย

ให้ Super Admin เพิ่มผู้ดูแลคนที่ 2 หรือผู้ดูแลเพิ่มเติมจากหน้า AVENZO ONE ได้โดยไม่ต้องใช้ SQL Editor พร้อมกำหนดระดับสิทธิ์ พักสิทธิ์ชั่วคราว เปิดสิทธิ์กลับ และบันทึก Audit Log

## ระดับสิทธิ์รอบแรก

- `super_admin` — ใช้งาน Control Plane และจัดการ Platform Admin คนอื่นได้
- `platform_admin` — ใช้งาน Control Plane และเป็นผู้อนุมัติคนที่ 2 ได้ แต่จัดการ Platform Admin ไม่ได้

## กฎความปลอดภัย

- ผู้ดำเนินการต้องเป็น Super Admin สถานะ Active และ Session ต้องเป็น MFA `aal2`
- ผู้รับสิทธิ์ต้องมีบัญชี Supabase Auth และยืนยันอีเมลแล้ว
- ห้ามผู้ดูแลเปลี่ยนหรือลดสิทธิ์บัญชีตัวเอง
- ห้ามพักหรือลดสิทธิ์ Super Admin คนสุดท้าย
- ทุกคำสั่งต้องมีเหตุผล 10–2,000 ตัวอักษรและ Command ID ป้องกันการบันทึกซ้ำ
- Browser ใช้ Publishable Key เท่านั้น การอ่าน `auth.users` และ MFA ทำใน RPC ฝั่ง Database
- ตาราง Audit อยู่ใน `private` schema และไม่เปิดให้ Browser อ่านหรือเขียนตรง

## UI

- เมนู `จัดการ Platform Admin` ที่ `/platform-admin/access`
- การ์ดเพิ่มผู้ดูแล: อีเมล ชื่อที่แสดง ระดับสิทธิ์ และเหตุผล
- หน้าตรวจสอบครั้งสุดท้ายก่อนบันทึก
- Directory แสดงสถานะ ระดับสิทธิ์ จำนวน Authenticator และเวลา Login ล่าสุด
- ปุ่มเปลี่ยนระดับสิทธิ์ พักชั่วคราว และเปิดสิทธิ์กลับ

## วิธีทดสอบ Local

1. Login ด้วย Super Admin และยืนยัน MFA
2. เปิด `/platform-admin/access`
3. ใช้อีเมลบัญชีที่สร้างและยืนยันอีเมลแล้ว เลือก `Platform Admin`
4. กดตรวจสอบก่อนเพิ่ม แล้วกรอกเหตุผลอย่างน้อย 10 ตัวอักษร
5. ยืนยันและตรวจว่ารายชื่อแสดงบัญชีใหม่เป็น Active
6. Logout แล้ว Login ด้วยบัญชีใหม่ ตั้งค่า MFA และตรวจว่าเข้า Control Plane ได้
7. ตรวจว่าบัญชีใหม่ไม่มีปุ่มเพิ่มหรือเปลี่ยนสิทธิ์ผู้ดูแล
8. Login กลับด้วย Super Admin และทดสอบพักสิทธิ์/เปิดสิทธิ์กลับ

## ขั้นต่อไป

หลัง Local ผ่าน ให้ขออนุมัติ Commit/Push/Deploy แยกต่างหาก แล้วกลับไปทดสอบ Two-person Approval ของ Phase 1.1.3.7.4
