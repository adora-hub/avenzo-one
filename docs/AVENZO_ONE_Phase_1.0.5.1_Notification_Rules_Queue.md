# AVENZO ONE — Phase 1.0.5.1 Notification Rules & Queue

อัปเดต: 7 สิงหาคม 2026

## เป้าหมาย

เตรียมกฎและคิวแจ้งเตือน Subscription ก่อนเชื่อมระบบส่งอีเมลจริง โดย Platform Admin สามารถตรวจสอบผลลัพธ์และเปิด/ปิดแต่ละกฎได้

## กฎเริ่มต้น

- ทดลองใช้จะสิ้นสุดใน 1 วัน
- Subscription จะหมดอายุใน 7, 3 และ 1 วัน
- เริ่มช่วงผ่อนผัน
- ช่วงผ่อนผันจะสิ้นสุดใน 1 วัน
- Subscription หมดอายุแล้ว

## Database Safety

- ตารางกฎและคิวเปิด RLS และอนุญาตเฉพาะ Platform Admin ที่ผ่าน MFA ระดับ AAL2
- เลือกผู้รับเฉพาะสมาชิกสถานะ Active ที่มี Role `owner`
- คิวเก็บ `recipient_user_id` ไม่ทำสำเนาอีเมลลงฐานข้อมูลใหม่
- `dedupe_key` เป็น Unique ป้องกันคิวซ้ำ แม้กดคำนวณหลายครั้ง
- ปิดกฎแล้วคิว Pending ของกฎนั้นเปลี่ยนเป็น Canceled; เปิดกลับแล้วคืนเป็น Pending
- การแก้กฎมี Audit Log แบบภายใน แก้ย้อนหลังไม่ได้

## UI

- ทางเข้าใหม่ “แจ้งเตือน Subscription” บนหน้า Platform Admin
- เปิด/ปิดกฎพร้อมคำอธิบายเวลาแบบภาษาคน
- ปุ่มคำนวณคิวแสดงจำนวนรายการใหม่ และบอกเมื่อไม่มีรายการซ้ำ
- ตารางคิว 10 รายการต่อหน้า พร้อม Pagination และช่องไปหน้าที่ต้องการ
- แสดงเวลาตาม Timezone ของ Organization

## ขอบเขตที่ยังไม่รวม

- ยังไม่ส่งอีเมลจริง
- ยังไม่มี Cron/Scheduler อัตโนมัติ
- ยังไม่มี Retry Worker และ Delivery Log จากผู้ให้บริการอีเมล

## Acceptance Criteria

1. กดคำนวณครั้งแรกสร้างคิวตามกฎให้ Owner
2. กดคำนวณซ้ำได้ผล 0 รายการและจำนวนคิวไม่เพิ่ม
3. ปิดกฎแล้วรายการ Pending ของกฎนั้นถูกยกเลิก
4. ผู้ที่ไม่ใช่ Platform Admin AAL2 อ่านหรือแก้กฎ/คิวไม่ได้
5. ไม่มีการส่งอีเมลจาก Phase นี้

## ผลการทดสอบ

- Migration ทั้ง 3 ชุดถูกใช้งานบน Supabase สำเร็จ
- สร้างคิวจริง 7 รายการจากกฎเริ่มต้น 7 กฎ และกดคำนวณซ้ำได้ 0 รายการใหม่
- ปิด/เปิดกฎกลับคืนสำเร็จ และมี Audit Log 2 เหตุการณ์
- Session ระดับ AAL1 อ่านกฎและคิวไม่ได้ (0 รายการ)
- TypeScript ตรวจผ่านด้วย `tsc --noEmit --incremental false`
- UI บัญชี Platform Admin แสดงกฎ 7 รายการ คิว 7 รายการ และไม่พบ Console Error
- Security Advisor ไม่พบคำเตือนใหม่จาก Schema ชุดนี้; ยังคงมีคำเตือนเดิมเรื่อง Leaked Password Protection ซึ่งต้องเปิดก่อน Production
- Performance Advisor ไม่พบ Foreign Key ที่ขาดดัชนีจาก Schema ชุดนี้
