# AVENZO ONE — Phase 1.1.3.8.5.3.2

## Approval Workflow Actions UI

สถานะ: Local ผ่าน

### เป้าหมาย

ทำให้ Platform Admin เห็นทันทีว่าบัญชีปัจจุบันทำอะไรได้ เหตุใดปุ่มจึงพร้อมหรือไม่พร้อม และต้องส่งงานต่อให้ใคร โดยไม่ลดกติกาความปลอดภัยฝั่ง Server

### Action ที่ระบบแสดง

| สถานการณ์ | ปุ่มและผลที่แสดง |
| --- | --- |
| ยอดหลักฐานไม่ตรง Invoice | ปุ่มปิด “ยอดไม่ตรง — ยังยืนยันไม่ได้” พร้อมเหตุผลให้แก้ข้อมูลก่อน |
| รายการใช้ผู้ดูแล 2 คน และบัญชีปัจจุบันเป็นผู้ตรวจคนแรก | ปุ่มปิด “รอ Platform Admin คนที่ 2” เพื่อป้องกันบัญชีเดิมอนุมัติซ้ำ |
| รายการใช้ผู้ดูแล 2 คน และบัญชีปัจจุบันเป็นอีกบัญชี | ปุ่มพร้อม “ตรวจทานและอนุมัติคนที่ 2” |
| รายการใช้ผู้ดูแล 1 คน | ปุ่มพร้อม “ตรวจสอบและยืนยันรับชำระ” หรือ “ตรวจทานและยืนยันรับชำระ” ตามผู้ดำเนินการ |

### ขอบเขตความปลอดภัย

- UI ปิดปุ่มที่ไม่ควรดำเนินการเพื่อช่วยผู้ใช้ แต่ไม่ถือเป็นชั้นความปลอดภัยหลัก
- RPC ฝั่ง Server ยังคงตรวจ Platform Admin, AAL2, ยอดเงิน, สถานะหลักฐาน และกฎผู้อนุมัติสองบัญชี
- การยืนยันสำเร็จยังสร้าง Payment, เปลี่ยน Invoice และต่อ Subscription ภายใน Transaction เดียว
- ไม่มี Secret Key ถูกส่งมายัง Browser

### วิธีทดสอบ Local

1. เปิด `/platform-admin/billing/transfer-proofs` ด้วย Platform Admin ที่ผ่าน MFA
2. รายการปกติที่ยอดตรง ต้องมีปุ่มยืนยันรับชำระที่กดได้
3. รายการที่ใช้ผู้ดูแล 2 คน เมื่อเปิดด้วยผู้ตรวจคนแรก ต้องเห็นปุ่มปิด “รอ Platform Admin คนที่ 2”
4. Login ด้วย Platform Admin อีกบัญชี รายการเดียวกันต้องมีปุ่ม “ตรวจทานและอนุมัติคนที่ 2” ที่กดได้
5. รายการยอดไม่ตรง Invoice ต้องเห็นปุ่มปิดและไม่เปิดการ์ดยืนยันขั้นสุดท้าย

### แผนถัดไป
