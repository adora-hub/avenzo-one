# AVENZO ONE — Phase 1.1.3.8.5.2

## Transfer Approval Policy Enforcement

สถานะ: Implemented / รอผู้ใช้ทดสอบ Local

### เป้าหมาย

บังคับใช้นโยบายจำนวนผู้อนุมัติสำหรับการรับชำระด้วยการโอนเงินจริงจากฝั่ง Server โดยไม่เชื่อการตัดสินใจจาก Browser

### กติกา

- ยอดไม่เกิน `single_admin_limit` และไม่ถูกระบุว่ามีความเสี่ยง: ผู้ตรวจหลักฐานคนเดิมยืนยันรับชำระต่อได้
- ยอดเกิน `single_admin_limit`: ต้องใช้ Platform Admin อีกบัญชีเป็นผู้ยืนยันรับชำระ
- เมื่อ `require_two_person_on_risk` เปิดอยู่และผู้ตรวจระบุว่ารายการเสี่ยง: ต้องใช้ Platform Admin อีกบัญชีเสมอ
- ผู้ตรวจต้องระบุเหตุผลความเสี่ยงอย่างน้อย 3 ตัวอักษร

### ขอบเขตความปลอดภัย

- ทุกคำสั่ง Review และ Fulfillment ต้องเป็น Platform Admin ที่ผ่าน MFA ระดับ AAL2
- Server โหลดและล็อกนโยบายล่าสุดก่อนคำนวณจำนวนผู้อนุมัติ
- การสร้าง Payment, เปลี่ยน Invoice, ต่ออายุ Subscription และบันทึก Event อยู่ใน Transaction เดียว
- ใช้ Command ID และข้อจำกัด Unique เพื่อป้องกันการกดซ้ำ
- Snapshot `approval_policy_version`, `approval_required_count`, วงเงิน และข้อมูลความเสี่ยงไว้สำหรับ Audit
- Browser ไม่ได้รับ Secret Key และไม่สามารถลดจำนวนผู้อนุมัติเองได้

### วิธีทดสอบ Local

1. ใช้บัญชี Platform Admin A ที่ผ่าน MFA เปิด `/platform-admin/billing/transfer-proofs`.
2. ทดสอบรายการยอดไม่เกิน 5,000 บาท: รับรองหลักฐานโดยไม่ติ๊กความเสี่ยง รายการต้องแสดง “ผู้ดูแล 1 คน” และ Admin A ยืนยันรับชำระต่อได้.
3. ทดสอบรายการยอดเกิน 5,000 บาท หรือรับรองโดยติ๊ก “รายการนี้มีสัญญาณเสี่ยง”: รายการต้องแสดง “ผู้ดูแล 2 คน” และ Admin A ต้องถูกห้ามยืนยันเอง.
4. Login ด้วย Platform Admin B ที่ผ่าน MFA แล้วเปิดหน้าเดิม ปุ่มยืนยันรับชำระต้องใช้งานได้.
5. หลังยืนยัน ตรวจว่า Invoice เป็นชำระแล้ว, Payment ถูกสร้างเพียงหนึ่งรายการ และ Subscription ต่ออายุ.

### ยังไม่ทำใน Phase นี้

- ไม่ Commit, Push หรือ Deploy จนกว่าผู้ใช้จะทดสอบ Local และอนุมัติ
- ไม่ทำการตรวจจับความเสี่ยงอัตโนมัติด้วย OCR หรือ Fraud Engine; ใช้การระบุโดยผู้ตรวจพร้อมเหตุผลก่อน
