# Phase 1.2.3 — Security Regression Test

## เป้าหมาย

ตรวจว่าระบบ Session, MFA, การกู้รหัสผ่าน การจัดการอุปกรณ์ และอีเมลแจ้งเตือนยังทำงานร่วมกันได้ หลังจบ Phase 1.2.2.5.5 โดยไม่เปิดเผย Token, Session ID ดิบ หรือ Secret ฝั่ง Server

## ส่วนที่ตรวจอัตโนมัติ

รันจากโฟลเดอร์ `web`:

```powershell
npm.cmd run test:session-security-regression
npx.cmd tsc --noEmit --incremental false
```

คำสั่งรวมตรวจเรื่องต่อไปนี้:

1. นโยบาย Idle Timeout, Absolute Timeout และเวลาเตือน
2. การลงทะเบียน Session หลัง Login, Auth Callback และ MFA
3. Heartbeat และการอัปเดตกิจกรรมแบบจำกัดความถี่
4. UI เตือนก่อน Session หมดอายุ
5. การบังคับ Logout เมื่อ Session หมดอายุหรือถูกเพิกถอน
6. หน้ารายการอุปกรณ์โดยไม่เปิดเผย Session ID ดิบ
7. ยกเลิก Session รายอุปกรณ์และอุปกรณ์อื่นทั้งหมด
8. ประวัติกิจกรรมความปลอดภัย
9. อีเมลแจ้งเตือนอุปกรณ์ใหม่และการป้องกันส่งซ้ำ
10. Password Recovery สำหรับบัญชีที่เปิด MFA

## ส่วนที่ต้องทดสอบด้วยบัญชีจริง

ใช้บัญชีทดสอบเท่านั้น และเริ่มจาก Local ก่อน Production

### ชุด A — Login และ MFA

1. เปิดหน้าต่าง Incognito
2. เข้า `/` และ Login ด้วยบัญชี Platform Admin ที่เปิด MFA
3. กรอกรหัส TOTP 6 หลัก
4. ต้องเข้าสู่หน้าที่มีสิทธิ์ได้ และ Session ใหม่ต้องปรากฏที่ `/account/security/sessions`

### ชุด B — อีเมลอุปกรณ์ใหม่

1. ทำชุด A ด้วย Browser หรืออุปกรณ์ที่ยังไม่เคยใช้
2. ตรวจ Inbox และ Spam ของบัญชีที่ Login
3. ต้องพบหัวข้อ `[AVENZO ONE] มีการเข้าสู่ระบบจากอุปกรณ์ใหม่`
4. Refresh หน้าเว็บหรือรอ Heartbeat อีกหนึ่งรอบ ต้องไม่มีอีเมลเหตุการณ์เดิมซ้ำ

### ชุด C — ยกเลิกอุปกรณ์

1. Login บัญชีเดียวกันค้างไว้อย่างน้อย 2 อุปกรณ์
2. อุปกรณ์หลักเปิด `/account/security/sessions`
3. ยกเลิกอุปกรณ์รองหนึ่งเครื่อง แล้วเปิดหน้าป้องกันบนอุปกรณ์รอง
4. อุปกรณ์รองต้องถูกส่งกลับหน้า Login แต่อุปกรณ์หลักยังใช้งานได้
5. ทดสอบ “ออกจากระบบอุปกรณ์อื่นทั้งหมด” และตรวจอีเมลสรุปหนึ่งฉบับ

### ชุด D — Password Recovery พร้อม MFA

1. Logout แล้วกด `ลืมรหัสผ่าน?`
2. เปิดลิงก์ล่าสุดจากอีเมลเพียงครั้งเดียว
3. หากบัญชีเปิด MFA ระบบต้องให้ยืนยัน TOTP 6 หลักก่อน
4. ตั้งรหัสผ่านใหม่อย่างน้อย 8 ตัวอักษร
5. Login ด้วยรหัสใหม่ต้องสำเร็จ และรหัสเดิมต้องใช้ไม่ได้

### ชุด E — Session Expiry

1. ใช้บัญชีทดสอบที่มีนโยบายเวลาสั้น หรือรอเวลาตาม Policy จริง
2. ก่อนหมดเวลา ต้องเห็นข้อความเตือนและเวลานับถอยหลัง
3. Idle Timeout สามารถกดใช้งานต่อได้ก่อนหมดเวลา
4. Absolute Timeout ต่อเวลาไม่ได้ และเมื่อหมดเวลาต้องกลับหน้า Login พร้อมเหตุผลภาษาไทย

## เกณฑ์ผ่าน

- Automated Regression และ TypeScript ผ่านทั้งหมด
- ไม่มี Runtime Error, Console Error หรือ API 5xx ในเส้นทางที่ทดสอบ
- Session ที่ถูกเพิกถอนไม่กลับมาใช้งานได้
- อุปกรณ์ปัจจุบันไม่ถูกยกเลิกจากคำสั่งยกเลิกอุปกรณ์อื่น
- Password Recovery ของบัญชี MFA ต้องผ่าน AAL2 ก่อนเปลี่ยนรหัส
- อีเมลหนึ่ง Security Event ส่งไม่เกินหนึ่งฉบับ
- ไม่พบ Token, Secret, Session ID ดิบ หรือ IP Address ใน UI และอีเมล
