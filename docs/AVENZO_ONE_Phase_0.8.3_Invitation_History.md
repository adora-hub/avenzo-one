# AVENZO ONE — Phase 0.8.3 Invitation History

สถานะ: ดำเนินการและติดตั้งฐานข้อมูลแล้ว

## เป้าหมาย

ปรับส่วน “คำเชิญล่าสุด” ให้ใช้งานได้เมื่อมีประวัติคำเชิญจำนวนมาก และทำให้ผู้ดูแลเข้าใจว่าควรทำอะไรกับคำเชิญแต่ละสถานะ

## สิ่งที่พัฒนา

- แสดงรายการมาตรฐานหน้าละ 10 รายการ
- ค้นหาด้วยอีเมลผู้รับคำเชิญ
- กรองสถานะ `pending`, `accepted`, `revoked` และ `expired`
- เปลี่ยนหน้าด้วยปุ่มก่อนหน้า/ถัดไป หมายเลขหน้า และช่องไปยังหน้าที่ต้องการ
- แสดงชื่อสาขาเมื่อคำเชิญจำกัดสิทธิ์เฉพาะสาขา
- แสดงวันที่สร้าง วันหมดอายุ และวันที่ตอบรับตามสถานะ (ตารางเดิมยังไม่มีเวลาที่ยกเลิกโดยเฉพาะ)
- คำเชิญที่รอตอบรับมีปุ่ม “คัดลอกลิงก์” และ “ยกเลิก”
- คำเชิญที่ตอบรับแล้วแสดงว่า “เสร็จสิ้น” และไม่มีปุ่มเปิดคำเชิญที่ทำให้สับสน
- คำเชิญที่ถูกยกเลิกหรือหมดอายุมีปุ่ม “เชิญใหม่” เพื่อเติมข้อมูลเดิมกลับเข้าแบบฟอร์ม

## การควบคุมสิทธิ์และข้อมูล

- การแบ่งหน้า ค้นหา และกรองทำที่ PostgreSQL เพื่อลดข้อมูลที่ส่งมายังหน้าเว็บ
- RPC สาธารณะเป็น `SECURITY INVOKER`; การทำงานที่ต้องใช้สิทธิ์สูงอยู่ใน schema `private`
- ตรวจ `auth.uid()` และ permission `member.read` หรือ `member.invite` ที่ฐานข้อมูลทุกครั้ง
- ป้องกันการเชิญสมาชิกที่ active ซ้ำ และแจ้งให้เปิดสิทธิ์สมาชิกที่ suspended แทนการสร้างคำเชิญใหม่
- คำเชิญ pending ที่พ้นกำหนดถูกมองเป็น `expired` และสามารถเชิญใหม่ได้
- Owner role เชิญได้เฉพาะ Owner ขององค์กร และเป็นสิทธิ์ระดับทั้งองค์กรเท่านั้น

## ผลการตรวจสอบ

- TypeScript: ผ่าน
- ประวัติ 18 รายการ: หน้าแรก 10 รายการ หน้าที่สอง 8 รายการ
- กรอง accepted และค้นหาอีเมล: ผ่าน
- ทดสอบลำดับ pending → expired → เชิญใหม่ → revoked ภายใน transaction แล้ว rollback: ผ่าน
- ผู้ไม่มีสิทธิ์อ่านประวัติ: ถูกปฏิเสธ
- เชิญสมาชิก active ซ้ำ: ถูกปฏิเสธ
- Supabase Security Advisor: ไม่มีคำเตือนใหม่จาก Phase 0.8.3

## รายการที่อยู่นอกขอบเขต Phase 0.8.3

- ปรับฟังก์ชันเดิม `current_user_org_permissions` ที่เป็น `SECURITY DEFINER`
- เปิด Supabase leaked-password protection
- ปรับ RLS policy เดิมของ `organization_invitations` เพื่อลด auth init-plan warning
